# Mission Reflection: Build the Cloud Infrastructure Blueprint

## Questions:

1. Which cloud infrastructure component do you think is the most important? Why?
2. How does Linux support cloud computing?
3. Why is technical documentation important before deploying infrastructure?
4. What new skills did you learn during this laboratory activity?
5. How has your GitHub portfolio improved after completing this mission?

---
This laboratory activity helped me understand cloud infrastructure better because I was able to actually explore the different parts and not just read about them. For me, compute is the most important component because it is where applications and processes are run. Without compute, storage and networking would not be able to do much because there would be no system to use the resources.

Linux also supports cloud computing because it is stable, flexible, and commonly used on cloud servers. During the activity, I saw how Linux commands can be used to check system information and manage resources. Learning commands like lscpu, free -h, df -h, and ip a made me feel more comfortable working with a server environment.

I also realized why technical documentation is important before deploying infrastructure. It helps organize the plan, explain the purpose of each component, and make the setup easier to understand. Good documentation can also help when problems happen because there is a record that can be checked and followed.

One of the new skills I learned was using Linux commands to investigate a server. I also learned how to create Markdown files, make tables, organize information, compare AWS, Azure, and GCP services, and create a simple cloud architecture diagram. These were things I had not practiced much before this laboratory.

Lastly, I think my GitHub portfolio improved because it now contains more complete and organized work. I was able to successfully add Laboratory 02 with my reports, comparisons, reflection, and screenshots. Overall, this activity gave me more confidence and practical experience that I can use in future cloud computing activities.
