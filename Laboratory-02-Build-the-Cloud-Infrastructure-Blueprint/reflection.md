# Mission Reflection: Build the Cloud Infrastructure Blueprint

## Questions:

1. Which cloud infrastructure component do you think is the most important? Why?
2. How does Linux support cloud computing?
3. Why is technical documentation important before deploying infrastructure?
4. What new skills did you learn during this laboratory activity?
5. How has your GitHub portfolio improved after completing this mission?

---
Completing this laboratory activity has given me a deeper understanding of cloud infrastructure and its core components. Among the four major components—compute, storage, networking, and operating system—I believe that compute resources are the most important. Compute resources, such as virtual machines and containers, serve as the "engine" of the cloud because they execute applications, process data, and run workloads. Without compute, even the best storage and networking would be useless since there would be nothing to process the data or deliver services to users. This is why cloud providers offer scalable compute options like EC2, Azure Virtual Machines, and Google Compute Engine to meet varying demands.

Linux plays a vital role in supporting cloud computing. As an open-source, secure, and highly customizable operating system, Linux is the foundation of most cloud environments. Major cloud providers offer Linux-based virtual machines as their primary compute options, and Linux supports essential cloud-native technologies such as Docker, Kubernetes, and Terraform. Its stability, performance, and strong community support make it the preferred choice for cloud deployments. Without Linux, the cloud computing industry would not be as robust and scalable as it is today.

One of the most important lessons I learned from this activity is the value of technical documentation before deploying infrastructure. Documentation ensures that all design decisions are clearly communicated, justified, and understood by the entire team. It helps engineers anticipate potential issues, plan for scalability, and ensure security and compliance. It also serves as a reference for future maintenance, troubleshooting, and onboarding of new team members. As the module emphasized, "Great cloud engineers build systems—but exceptional cloud engineers document and justify every design decision."

Throughout this laboratory, I developed several new skills. I learned how to investigate a Linux server using commands such as `lscpu`, `free -h`, `df -h`, and `ip a` to identify compute, storage, and networking resources. I also learned how to create professional technical documentation using Markdown, including tables, headings, and lists. Additionally, I gained experience in comparing cloud services across AWS, Azure, and GCP by researching their official documentation, and I designed a simple cloud architecture diagram using Canva. These skills are essential for any aspiring cloud engineer.

Finally, my GitHub portfolio has significantly improved after completing this mission. Before this activity, my repository only contained the files from Laboratory 01. Now, I have a complete and well-organized folder for Laboratory 02 with all required files, including `infrastructure-report.md`, `cloud-components.md`, `cloud-provider-comparison.md`, `reflection.md`, and a `screenshots/` folder containing four PNG images. My `README.md` is now comprehensive, with clear sections documenting the entire process. This structured approach demonstrates my ability to manage cloud projects professionally and showcases my technical and documentation skills to potential employers or instructors. Overall, this laboratory activity has been a valuable learning experience that has prepared me for more advanced cloud computing topics.
