# Reflection

Automation is important when managing hundreds of cloud servers because it saves time and makes work easier. Instead of doing the same tasks manually on every server, administrators can use scripts to perform tasks automatically. This also helps reduce human errors and makes system management more efficient.

However, automation can also be dangerous when a script contains mistakes. For example, if a script has a command that accidentally deletes important files and is scheduled to run on 1,000 servers, it could cause serious data loss across many systems. This is why scripts should be checked and tested first before running them, especially when managing important servers and data.

Writing a Bash script was different from creating a Docker Compose YAML file in Mission 6. In Bash, I had to write commands that would run step by step to create a backup of my files. In Docker Compose, I used a YAML file to define and manage containers and services. Both can make tasks easier, but Bash is more focused on executing commands while Docker Compose is used to manage containerized applications.

From Laboratory 1 to Laboratory 9, my understanding of Cloud Computing has improved because I learned that it involves more than just running applications online. I also learned about containers, data storage, cloud operations, security, and automation. Each laboratory helped me understand how different tools are used to manage systems and solve problems. I realized that managing cloud infrastructure requires not only technical skills but also careful planning and testing.

Among the different roles, I enjoyed the Cloud Operations Engineer role the most because I learned how to monitor systems, check resources, and automate tasks. I liked seeing how commands and scripts could make work easier and more organized. This laboratory also taught me that automation is helpful, but it still requires proper testing and monitoring to make sure everything works correctly.
